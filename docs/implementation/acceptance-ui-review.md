## Fixture isolation, retries and timing

- `helpers/fixtures.ts` supplies fallback credentials and a fallback organization ID without verifying provisioned identity; organization ID is not used to assert tenant scope. Require explicit synthetic credentials and verify the isolated runtime identity. No bootstrap occurs in the suite.
- All four PDF fixture paths point at the older absolute snapshot directory. Resolve approved synthetic fixtures relative to a declared current source root and verify bytes/hash. File availability alone does not establish the oracle for the current application.
- `workers: 1` and `fullyParallel: false` do not provide database isolation, cross-file fixture dependencies or retry cleanup. Tests select first cases/parties/documents, and bootstrap creates zero cases. Running files individually or after a failed create can fail or mutate unrelated records. Four-digit timestamp suffixes and fixed references are collision-prone. Allocate explicit IDs and a random run namespace in a fresh disposable tenant/DB; discard it through the lead's lifecycle rather than deleting arbitrary application records.
- CI retries once against the same persistent mutations; there is no per-attempt fixture reset or stable retry ownership. A retry can produce duplicates or operate on another first record. Disable retries until isolation/idempotency and cleanup semantics are deliberate.
- Fixed 300 ms search, 1 s review and 500 ms fragment waits are not completion oracles. Search is a local current-page filter, not a guaranteed debounced server search. Poll required observable state or authenticated reads with bounded deadlines. Assert failed terminal states explicitly.
- Global test timeout 45 s, assertion/action timeouts 10 s and navigation timeout 15 s are not a realistic extraction completion budget. Current workspace polls jobs every 3 s for up to five minutes; worker/provider deadlines are separate. Use a bounded pipeline-specific budget without silently bypassing unfinished work.
- Config defaults to frontend `127.0.0.1:3000`; the respondent context ignores the configurable origin. Default scripts/config include three browser projects, while package dependencies use unpinned compatible ranges and no package lock was supplied. Record exact dependency/browser versions in the lead's run. `ignoreHTTPSErrors: true` must not be mistaken for TLS acceptance.
- Failure traces/videos/screenshots can retain login bodies and invitation fragments. External artifact configuration is unsuitable unchanged for this capability flow. Private synthetic artifacts still require credential/token exclusion; do not retain raw request/error/page dumps.
