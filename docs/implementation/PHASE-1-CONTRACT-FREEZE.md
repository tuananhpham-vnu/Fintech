## Technical normalizations frozen for this slice

- Retain NestJS and cookie session architecture. Use `pg` with explicit parameterized SQL and versioned SQL migrations: no existing ORM to preserve, the slice needs explicit composite FKs/locks/transactions, and introducing Prisma/TypeORM would add generated metadata and migration ownership without removing these invariants. Migrations use a single client, advisory lock, checksum, transaction, and no automatic production startup migration. [Driver transaction guidance](https://node-postgres.com/features/transactions).
- SQL schema `aic` isolates application tables. UUIDs server-generated; timestamptz UTC; wire revisions safe positive integers. Exposure VND is retained as a string in JSONB with a positive24-digit CHECK (the draft numeric(24,0) capacity), without floating-point conversion or a second mutable amount column. Financial numeric columns and the complete Exposure write schema remain pending. CHECK/FK/NOT NULL and RESTRICT express frozen requirements; table definitions live only in numbered SQL migrations with a single writer. Organization tax-ID requiredness is not released as a business write rule; its nullable internal column supports operator/bootstrap records without asserting verified identity.
- Session tokens: random32 bytes, only SHA-256 hash stored; CSRF derived by HMAC-SHA256 keyed by the opaque session token over a versioned label, only CSRF hash stored. Login/me return CSRF, never session token in JSON. Password: versioned scrypt encoding with per-password salt and timing-safe comparison; algorithm parameters versioned, not a password-content policy.
- Session TTL/idle and login limits use the temporary technical values explicitly authorized by the owner, overridable in environment config. They are **not final security policy**. Idempotency retention still requires an explicit setting; no default production retention or automatic deletion/reuse is introduced.
- Login throttling persists one hashed account+socket-peer bucket in PostgreSQL, failed attempts only. Do not trust forwarded IP headers by default. Attempts are serialized per bucket; avoid storing raw account/password/IP in throttle/audit rows. No account-only lockout or unapproved global-IP threshold; trusted ingress/client-IP behavior behind Next remains a deployment decision.
- Idempotency JSON hash: recursively sort object keys, preserve array order and null vs absent, SHA-256 UTF-8 JSON of case ID + expected revision + payload; scope organization+actor+operation+case+key (case bound into operation storage value). Transaction-scoped advisory lock serializes same scope; response JSON/status and business/audit/revision commit together. Authentication/current ACL is rechecked inside transaction before replay. Expired records are not silently reused: conflict until an explicit retention/cleanup policy is approved. This is an executable Unit-of-Work primitive, not a release of pending business mutation routes.
- Core reads return existing FE envelopes; stable cursor pagination orders updated_at/id DESC. No data envelope. Generic unauthorized/outsider/DB errors contain no resource metadata or connection credentials. Error request_id is server-generated UUID; query/credentials excluded from request logs.
- Production/default application only wires the foundation. Legacy RAM/upload/gold mapping is isolated in an explicit test-only entry point (`NODE_ENV=test`, `AIC_RUNTIME_MODE=prototype`, explicit enable flag). Existing feasibility test is retained unchanged for that entry point, and its wrong400 assertion does not define the new contract.

## Pending business or wider-contract decisions — do not implement from assumptions

1. Sharing/transfer/grant-revoke beyond creator membership remains pending. Owner explicitly approved creator membership in the same transaction as case creation, same organization only, no organization-wide grants. Case creation still blocked by pending effective approved policy selection and Exposure write schema.
2. Policy selection/version registry for new cases. No invented transport-test policy for production records.
3. Exposure conditions/paid-received claims/source bindings, nullable term explanation, provenance/external sources, and identity changes that stale assessments. No PATCH exposure/counterparty or create writes from incomplete shapes. Storage shape can retain existing JSON, but this does not release its mutation schema.
4. Final security-policy and idempotency-retention approval. Owner supplied temporary technical settings during this phase: absolute TTL8h, idle30min, HttpOnly/Secure(production)/SameSite=Lax, maximum5 failed attempts per account/IP in15min followed by15min block. These are configurable implementation/test settings, not final business/security policy. No account-only lockout: another IP cannot lock this account's bucket. Idempotency retention has no approved default, remains explicit config and no automatic cleanup/reuse.
5. Documents/evidence/jobs/review/waiver/financial/method/capability schemas and workflow gates are out of Phase1. No tables or fake readiness/history/score for them.
