# AIC foundation and local MVP sandbox contract

Owner: Lead. Current wire bundle **0.4.0-mvp-sandbox**; JSON Schema Draft7 and OpenAPI3.1, generated by `node scripts/generate-foundation-contract.cjs`. Inputs reject unknown fields; response validation runs in Nest. Shared contracts and migrations have one writer. Legacy AI bundle1.0.2 remains unchanged.

Default foundation scope is login/me/logout, organization-scoped counterparty reads, organization+membership case/history reads. Organization/User provisioning is operator-only. Additional sandbox routes require explicit `AIC_DOCUMENT_RUNTIME=local` and refuse production configuration; there is no public signup/admin role or implicit organization-wide case access.

Released local scope: unresolved counterparty create/edit with source versions, core case/Exposure including exact questionnaire response sources, immutable documents/exact source reads, strict legacy AI transport, bounded worker/manual retry, classification/correction/correct-value verification, independent Transaction Review, requests/exports/ack, waiver/revoke, issue decisions, optional staff questionnaires and native capability form/submit/receipt/revoke/close, financial set/fact registry and gated ratios. See implementation report/owner decisions and review handoff. Questionnaire verification confirms source fidelity, not identity/settlement/financial eligibility. Requiredness/skip policy is server-owned.

Review `findings` remain current detector observations; additive `issue_history` preserves older findings for specialist disposition. New decisions require a fresh review with `source_snapshot_hash`. Existing immutable review payloads without these additive fields stay readable. Resolve requires exact current reviewed complete sources; dismissal/reopen cannot remove underlying gates. Source/input changes invalidate dispositions. Case revision/audit/replay/decision or response write commit together under current authentication and ACL; exact replay precedes stale revision rejection.

Case-policy artifact/version/hash stays separate from question policy `MVP-OPTIONAL-TEXT-1` and financial method version. Numeric FHI activation/PD, verified settlement, legal identity confirmation, public ingress/trusted proxy and production retention guarantees remain unreleased. Native capabilities are controlled local flows only, not public deployment approval. Financial engine reference calculations cannot authorize app scores.

Invitations bind immutable form ID/version1 and exact question IDs. First create sends raw secret once in `X-Invitation-Token`; frozen JSON body has metadata only. Replay never returns secret. Reissue for same form/party/recipient revokes older invitations. Respondent bearer routes omit specialist session/CSRF, require allowed Origin on submit, use one submission per invitation and stable-key exact replay24h while currently valid; different payload/key409. No legal identity assurance. Definition changes require a new draft/form/invitation.

Financial registry GET supports optional `set_id`, scoped to this case; multiple sets require explicit selection to calculate ratios. Unit normalization is explicit, no period/basis/currency blending. Source/fact/bridge verification append-only and current-source-sensitive. All app points/score/band/grade/PD null while method unconfigured. Pure reference trace and canonical30 gap are documented in `FHI-ENGINE-REFERENCE.md`.

Migrations0001–0017 and current `scripts/sandbox-runtime-grants.sql` are required for local runtime. No auto-migration or seed-on-start. This bundle does not declare complete AIC2/business release, competition acceptance or production readiness.
